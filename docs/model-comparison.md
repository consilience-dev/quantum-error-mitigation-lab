# Comparing pretrained regressors on ML-QEM

The first comparison asks whether a general-purpose tabular regressor improves four-qubit observable estimates on IBM Algiers when it receives the same calibration labels and input features as the published hardware random forest. A second comparison asks whether updating a checkpoint's weights improves its predictions for those same circuits. Testing transfer to an independent device and circuit family is a separate experiment.

## Interpreting the model screen

The fresh split holds out new circuits from the same acquisition campaign. Repeated calibration draws quantify sensitivity to label selection. All draws share one test set. The original published rows and the fresh split come from the same source population and can overlap across experiments. Treat their agreement as a sensitivity check. A broad leaderboard increases the opportunity to select a winner by chance.

On the fresh split, compare each model's four-observable error against the paired forest, average paired circuit differences across available calibration seeds, then resample hardware batches. Report the number of completed seeds for each model. Label nominal intervals descriptive throughout this exploratory comparison. Compare full versus descriptor-only inputs using the *same* model, circuit IDs, weights and inference settings, alongside measurement-only inputs. This tests whether measurements add predictive information on this family. The total calibration count is a label budget. Claims about shot cost or hardware runtime additionally require acquisition costs for every comparator, including ZNE.

A confirmatory external study should freeze the model, conventional comparator, estimand and claim before scoring its test set. The [Placidi et al. hardware release](https://zenodo.org/records/18541433) lists separate `algiers_random_real_train.tgz` and `hanoi_random_real_test.tgz` archives. One concrete transfer experiment would train with 500 unique Algiers circuits and derive the same five single-qubit Z expectations from each ideal and noisy 32-outcome distribution. Audit bit order and shared logical circuit IDs across archives first. Fix a measurement-only input and a comparator such as per-observable affine regression to isolate transfer of a measurement correction, and pair each prediction with the raw Hanoi measurement. A circuit-aware follow-up should also include descriptor-only and full-input controls on the same circuits. The [Qermit experimental archive](https://doi.org/10.5281/zenodo.6472281) offers an additional check across circuit families and devices. These external studies remain prospective.

Model provenance also matters for interpretation. Nori's model card describes pretraining on synthetic tables. For checkpoints pretrained on real tables, document whether the training corpus and dataset exclusions can be inspected. This hardware release predates several checkpoints. An undisclosed pretraining corpus leaves potential benchmark exposure unresolved, even when the downstream calibration and test partitions are clean. Comparing frozen and tuned versions estimates the effect of the adaptation procedure for a given checkpoint. Isolating the causal effect of pretraining would additionally require a matched initialization/training ablation.
